# Capital voice sync, admin navigation, and security audit trail

## 1. Voice command: repayment sync summary
Extend the Capital voice assistant so a question like "when did it last sync?" returns a spoken summary of the last partner webhook event and the last repayment pg_cron run — each with a timestamp and whether it succeeded or failed, plus the most recent successful sync if the latest one failed. Add matching quick-question chips in English, Kiswahili, Sheng' and Kenglish.

## 2. Fix System Health / SEO Monitor tab navigation
Replace the two separate admin routes' isolated layouts with one shared admin monitoring shell that has proper tab navigation (System Health, SEO Monitor, Security). Tabs drive the URL so deep links and back/forward work. Non-admins see a single clear "Admin access required" state instead of a broken or half-rendered page; the admin nav links only appear for admins.

## 3. Security scan panel in System Health
New section showing the latest scan run: overall status, last-scanned timestamp, counts by severity, and a list of findings with their current status. Includes a rate-limited "Run scan now" action (existing quota logic reused).

## 4. Security update audit log
Every scan trigger and every finding status change (open → fixed / ignored) is recorded with who did it, when, which finding, old and new status, and the note. Surfaced as a read-only timeline under the security section, admin-only.

## 5. Notifications on scan completion and status change
When a scan finishes or a finding's status changes, create in-app notifications for admins, honouring the existing notification preference centre (in-app / email / Slack).

## 6. Admin-side Capital exports
Add CSV and PDF export buttons per application on the admin Capital pages, covering the application timeline and its audit log entries — mirroring the export already available to owners on /capital.

## 7. Regression tests
Automated tests that assert:
- a business owner calling the repayment RPC is rejected; admin/service-role succeeds
- concurrent wallet debits cannot overdraw the balance (atomicity holds)
- partner webhook secrets and SACCO key hashes stay admin-only

Wired into the existing security CI workflow so failures block merges.

## 8. Re-scan and verify
Run the security scan after the above work, confirm the five previously fixed findings stay resolved, and report anything new. Any new finding is triaged, not silently ignored.

- Navigation: new `src/pages/admin/AdminMonitoring.tsx` shell wrapping the existing `AdminHealth` / `AdminSEO` content as tab panels at `/admin/monitoring/:tab`, with the old paths redirecting; keeps `RequireAdmin` as the single gate.
- Audit: new `security_audit_events` table (admin-read, service-role write) plus a trigger on `security_findings` status changes; grants and RLS included in the migration.
